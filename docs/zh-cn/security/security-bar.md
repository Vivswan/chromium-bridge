# 安全标准线

本项目对你的浏览器作出了什么承诺, 又没有承诺什么。具体机制由[威胁模型](threat-model.md)和[信任边界](trust-boundaries.md)负责; 本页说明这些机制是为了什么。

## 一句话说清标准线

**你安装的程序无法在你毫无察觉的情况下使用你的浏览器。**

标准线不是什么: 它不是「任何东西都永远碰不到你的浏览器」。你安装这个桥接, 就是为了让 AI 代理 (agent) 能操作你的浏览器。标准线是本项目对自己的要求, 并非声称今天在所有地方都已达到。

有一处刻意未达标。在已批准的源 (origin) 上, 包括脱敏后的 Cookie 与存储在内的读取操作无需逐个操作确认即可运行, 而标签页标题和 URL 则完全无需批准就能读取 ([工具风险矩阵](tool-risk-matrix.md))。[我们刻意止步之处](#我们刻意止步之处)和[各系统对照表](#标准线今天在各系统上的落实)记载了这一点; [威胁模型的残余风险](threat-model.md#残余风险-已接受已跟踪)负责每一个已接受的缺口。

## 为什么浏览器就是资产

已登录的浏览器持有活跃的会话 Cookie。谁拿到它们, 谁就能以你的身份登录那些站点, 绕过你已经输入过的密码和第二因素。[威胁模型的资产清单](threat-model.md#资产)正因如此把会话放在首位。

## 不要成为最廉价的那扇门

本节是标准线背后的设计论证, 而非某种机制。在每一种操作系统上, 直接窃取 Cookie 都已经要让攻击者付出一些代价。一个任何本地程序都能免费访问的桥接, 代价比那还低, 而攻击者总是选最廉价的那扇门。

| 平台 | 直接读取 Cookie 存储 | 低门槛的 localhost 桥接 |
| --- | --- | --- |
| macOS | Cookie 密钥存放在登录钥匙串 (Keychain) 中; 除非用户此前已允许过该应用, 否则另一个应用读取它会触发钥匙串提示 | 静默 |
| Windows | 应用绑定加密 (app-bound encryption): 一个 SYSTEM 权限的服务只向浏览器本身释放密钥, 因此同用户进程需要 SYSTEM 权限或向浏览器注入代码 | 静默 |
| Linux | 密钥存放在会话的密钥存储 (secret store) 中, 或是一个固定的回退值; 处于已解锁会话中的同用户进程读取它不会有任何提示 | 静默 |

左列描述的是浏览器厂商公布的保护措施。这是关于其他软件的说法, 不是本项目所测试的内容。

本项目由此得出的结论: 一个静默的桥接会拉低机器原有的门槛。在门槛本已很低的地方, 比如 Linux 上, 桥接至少不能再添一扇免费的门。

## 谁在攻击, 各由什么应对

这个排序是本项目对现实中发生频率的判断, 不是测量结果。

| 排名 | 攻击者 | 由什么应对 | 负责方 |
| --- | --- | --- | --- |
| 1 | 来自代理正在阅读的页面的提示注入 | 站点白名单; 在扩展拥有的、位于页面 DOM 之外的窗口上进行确认; 对离开浏览器的内容进行脱敏 | [主要威胁](threat-model.md#主要威胁与缓解措施)、[边界 4](trust-boundaries.md#边界-4-扩展---网页-chrome-api--内容脚本--dom) |
| 2 | 你安装的、并非已配对客户端程序 (harness) 的粗糙或被攻陷的软件 (某个 npm 包、另一个 MCP 服务器、某个 IDE 扩展), 以你的用户身份、在不同的可执行文件身份下运行 | 对启动服务器的客户端程序进行证明; 已配对客户端白名单, 一旦配对了一个客户端即开始强制执行; 配对以用户在场为门槛 | [边界 1](trust-boundaries.md#边界-1-mcp-客户端---rust-mcp-服务器-stdio-json-rpc-20)、[新的信任边界](threat-model.md#重建带来的变化-新的信任边界) |
| 3 | 已经以你的身份运行的持久化恶意软件 | 设计上不在范围内; 本项目只是拒绝让它的工作变得更容易 | [明确的非目标](threat-model.md#明确的非目标) |

## 我们刻意止步之处

- **已批准站点上不做逐次读取提示。** 在白名单源上的读取, 包括脱敏后的 Cookie 和存储, 都不经提示即运行, 因为几乎每一步都弹提示, 会让用户养成直接点掉那些守护危险操作的提示的习惯。负责方: [残余风险](threat-model.md#残余风险-已接受已跟踪)与[工具风险矩阵](tool-risk-matrix.md)。
- **已批准站点上的点击宽限期。** 一次已批准的提交或链接点击之后, 同一源与同一操作类型在一段较短的默认时间窗内跳过提示; `page_eval` 永远不会跳过。负责方: [安全策略中的确认默认值](../../../.github/SECURITY.md#page_eval-and-confirmation-defaults-fail-safe)。
- **接受同用户重新执行我们自己的二进制。** 证明机制拒绝的是不同的程序, 而非由同用户攻击者启动的真正二进制。负责方: [明确的非目标](threat-model.md#明确的非目标)。
- **被攻陷的已配对客户端程序保留其已准入的身份。** 证明机制识别的是二进制而非意图, 因此一个变得恶意的已配对客户端在被吊销之前始终受信任。负责方: [新的信任边界](threat-model.md#重建带来的变化-新的信任边界)下的客户端程序准入条目。
- **在没有硬件在场能力的地方, 软件在场回退会被明确标注。** 没有 Secure Enclave 密钥时, 在场只是一次软件确认, 它能阻止静默和脚本化的操作, 但挡不住恶意的同用户进程。负责方: [新的信任边界](threat-model.md#重建带来的变化-新的信任边界)下的紧急开关 (kill switch) 条目。

## 标准线今天在各系统上的落实

在每一种操作系统上, 客户端程序准入都只在配对了一个客户端之后才强制执行; 在此之前, 服务器为任何启动它的进程提供服务。

| 操作系统 | 客户端证明 | 用户在场 | 标准线在哪里成立 |
| --- | --- | --- | --- |
| macOS | 启动服务器的客户端程序的代码身份, 对照已配对客户端白名单检查 ([边界 1](trust-boundaries.md#边界-1-mcp-客户端---rust-mcp-服务器-stdio-json-rpc-20)) | 已登记的 Mac 上为硬件在场; 否则为软件回退 | 成立: 桥接只准入由本用户运行、持有运行密钥 (run secret) 的本二进制 ([边界 2](trust-boundaries.md#边界-2-rust-mcp-服务器---原生消息主机-桥接套接字-ndjson)) |
| Linux | 启动服务器的客户端程序的代码身份, 对照白名单检查 ([边界 1](trust-boundaries.md#边界-1-mcp-客户端---rust-mcp-服务器-stdio-json-rpc-20)) | 仅软件回退 | 对桥接成立, 门禁相同; 在场由软件证明 |
| Windows | 启动服务器的客户端程序的映像哈希与 Authenticode 发布者, 对照白名单检查 ([边界 1](trust-boundaries.md#边界-1-mcp-客户端---rust-mcp-服务器-stdio-json-rpc-20)); Windows 上的配对见 [CLI 页面](../cli.md#受信任客户端-pair-client--revoke-client--list-clients) | 仅软件回退 | 对桥接成立: 只有本用户能打开的命名管道、相互映像证明、运行密钥 ([边界 2](trust-boundaries.md#边界-2-rust-mcp-服务器---原生消息主机-桥接套接字-ndjson)); 在场由软件证明 |

该行背后的 Windows 残余风险见[威胁模型](threat-model.md#残余风险-已接受已跟踪); [安全策略中的平台表](../../../.github/SECURITY.md#platform-support)负责各机制的具体状态。

## 对照便利优先的设计流派

浏览器自动化的一种常见设计把便利放在首位。左列以定义该流派的几项选择来描述它, 其中浏览器如何响应是关于其他软件的说法; 这里不点名任何产品。

| 要点 | 便利优先的设计流派 | 本项目 |
| --- | --- | --- |
| 谁能访问桥接 | 一个对任何本地进程开放的 localhost 端口 | 只有由本用户运行、持有运行密钥的本二进制 ([边界 2](trust-boundaries.md#边界-2-rust-mcp-服务器---原生消息主机-桥接套接字-ndjson)) |
| 调试端口及其横幅 | 一个随时对任何本地进程开放的调试端口; 浏览器的调试横幅只在有客户端附加时显示, 所以两次附加之间用户什么也看不到 | 没有调试端口; 横幅只在由调试器支撑的工具或选择启用的 CDP 模式持有附加时显示 ([工具风险矩阵](tool-risk-matrix.md)标出了是哪些工具) |
| 默认访问 | 从第一次调用起就对所有站点拥有完整访问权 | 页面操作与读取只在用户批准过的站点上运行, 标签页标题和 URL 除外, 它们无需批准; 风险最高的工具在主机持有的策略下默认关闭 ([工具风险矩阵](tool-risk-matrix.md)) |
| 逐操作确认 | 无 | 默认情况下, 受确认门禁的操作在页面无法触及的窗口上确认 ([工具风险矩阵](tool-risk-matrix.md)列出了这些操作), 其中风险最高的两个在已登记的 Mac 上需要硬件在场; 放宽某个门禁是一次以在场为门槛的策略变更 ([确认默认值](../../../.github/SECURITY.md#page_eval-and-confirmation-defaults-fail-safe)) |
| 本地恶意软件 | 声明不在范围内, 且不做任何处理 | 同样不在范围内, 但桥接拒绝成为最廉价的那扇门: 在 macOS 和 Linux 上, 不同的同用户程序在套接字处即被拒绝; 而一旦配对了一个客户端, 每个客户端程序都必须匹配白名单, 配对则需要用户在场 |

## 未来变更的规则

本页为评审标准增加一条规则: 每一项与安全相关的变更都要指明它移动了本页的哪一行、朝哪个方向, 或者说明没有任何行移动以及原因。[安全策略中的评审标准](../../../.github/SECURITY.md#security-relevant-changes-review-bar)定义了哪些变更算数。
