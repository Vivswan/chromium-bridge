# 安全標準線

本專案對你的瀏覽器承諾什麼, 又不承諾什麼。各項機制由[威脅模型](threat-model.md)與[信任邊界](trust-boundaries.md)擁有; 本頁說明這些機制是為了什麼。

## 一句話說清標準線

**你安裝的程式無法在你毫無察覺的情況下使用你的瀏覽器。**

這條標準線不是「任何東西都永遠碰不到你的瀏覽器」。你安裝這個橋接, 就是為了讓代理程式操作你的瀏覽器。這條標準線是專案對自己的要求, 而不是宣稱今天已經處處達標。

有一處刻意未達標。在已核准的來源 (origin) 上, 包含遮罩後的 Cookie 與儲存空間在內的讀取操作不會逐次提示, 而分頁標題與 URL 則完全不需核准即可讀取 ([工具風險矩陣](tool-risk-matrix.md))。[我們刻意止步之處](#我們刻意止步之處)與[各系統對照表](#標準線今天在各系統上的落實)記載了這一點; [威脅模型的殘餘風險](threat-model.md#殘餘風險-已接受已追蹤)則擁有每一項已接受的缺口。

## 為什麼瀏覽器就是資產

已登入的瀏覽器持有有效的工作階段 Cookie。誰拿到這些 Cookie, 誰就能以你的身分登入那些網站, 繞過你已經輸入過的密碼與第二因素。[威脅模型的資產清單](threat-model.md#資產)正因如此把工作階段排在第一位。

## 不要成為最廉價的那扇門

本節是標準線背後的設計論證, 不是機制。在每個作業系統上, 直接竊取 Cookie 都已經要讓攻擊者付出一些代價。一個任何本機程式都能免費觸及的橋接, 代價比那還低, 而攻擊者總是挑最廉價的那扇門。

| 平台 | 直接讀取 Cookie 儲存區 | 低門檻的 localhost 橋接 |
| --- | --- | --- |
| macOS | Cookie 金鑰存放在登入鑰匙圈中; 其他 app 讀取它會觸發鑰匙圈提示, 除非使用者先前已允許該 app | 無聲無息 |
| Windows | 應用程式繫結加密: 由 SYSTEM 權限的服務只把金鑰釋出給瀏覽器本身, 因此同一使用者的程序需要 SYSTEM 權限或對瀏覽器進行程式碼注入 | 無聲無息 |
| Linux | 金鑰存放在工作階段的秘密儲存區, 或一個固定的備援值; 在已解鎖的工作階段中, 同一使用者的程序讀取它不會有任何提示 | 無聲無息 |

左欄描述的是瀏覽器廠商公開的保護措施。那是關於其他軟體的陳述, 不是本專案測試過的事。

專案由此得出的結論: 一個無聲的橋接會拉低這台機器原本就有的門檻。在門檻原本就低的地方 (例如 Linux), 橋接至少不能再多添一扇免費的門。

## 誰在攻擊, 各由什麼應對

這個排名是本專案對真實世界發生頻率的判斷, 不是量測結果。

| 排名 | 攻擊者 | 由什麼應對 | 擁有者 |
| --- | --- | --- | --- |
| 1 | 來自代理程式正在讀取的頁面的提示注入 | 網站允許清單; 在擴充功能擁有、脫離頁面 DOM 的視窗上確認; 對離開瀏覽器的內容進行遮罩 | [主要威脅](threat-model.md#主要威脅與緩解措施)、[邊界 4](trust-boundaries.md#邊界-4-擴充功能---網頁-chrome-api--內容指令碼--dom) |
| 2 | 你安裝的、粗糙或已遭入侵、且不是已配對用戶端程式 (harness) 的軟體 (某個 npm 套件、另一個 MCP 伺服器、某個 IDE 擴充功能), 以你的使用者身分、用不同的執行檔身分執行 | 對啟動伺服器的用戶端程式進行證明; 已配對用戶端允許清單, 自第一個用戶端配對起強制執行; 配對以使用者在場為閘門 | [邊界 1](trust-boundaries.md#邊界-1-mcp-用戶端---rust-mcp-伺服器-stdio-json-rpc-20)、[新的信任邊界](threat-model.md#重建帶來的變化-新的信任邊界) |
| 3 | 已經以你的身分執行的持續性惡意軟體 | 依設計不在範圍內; 本專案只是拒絕讓它的工作變得更容易 | [明確的非目標](threat-model.md#明確的非目標) |

## 我們刻意止步之處

- **已核准網站上不逐次提示讀取。** 在允許清單中的來源上, 讀取操作 (包含遮罩後的 Cookie 與儲存空間) 不經提示即執行, 因為幾乎每一步都提示, 會教使用者習慣性地點掉那些守護危險動作的提示。擁有者: [殘餘風險](threat-model.md#殘餘風險-已接受已追蹤)與[工具風險矩陣](tool-risk-matrix.md)。
- **已核准網站上的點擊寬限期。** 一次已核准的送出或連結點擊之後, 同一來源與同一動作類型在一段短暫的預設期間內跳過提示; `page_eval` 永遠不會。擁有者: [安全策略中的確認預設值](../../../.github/SECURITY.md#page_eval-and-confirmation-defaults-fail-safe)。
- **接受同一使用者重新執行我們自己的執行檔。** 證明拒絕的是不同的程式, 而不是由同一使用者的攻擊者啟動的正版執行檔。擁有者: [明確的非目標](threat-model.md#明確的非目標)。
- **已遭入侵的已配對用戶端程式保有其已准入的身分。** 證明識別的是執行檔, 不是意圖, 所以一個轉為敵意的已配對用戶端在被撤銷之前仍然受信任。擁有者: [新的信任邊界](threat-model.md#重建帶來的變化-新的信任邊界)下的用戶端程式准入條目。
- **沒有硬體在場的地方, 軟體在場備援會被明確標示。** 沒有 Secure Enclave 金鑰時, 在場只是一次軟體確認, 能阻止無聲與指令碼化的操作, 但擋不住敵意的同一使用者程序。擁有者: [新的信任邊界](threat-model.md#重建帶來的變化-新的信任邊界)下的緊急開關 (kill switch) 條目。

## 標準線今天在各系統上的落實

在每個作業系統上, 用戶端程式准入都只在第一個用戶端配對之後才強制執行; 在那之前, 伺服器為任何啟動它的程式提供服務。

| 作業系統 | 用戶端證明 | 使用者在場 | 標準線守在哪裡 |
| --- | --- | --- | --- |
| macOS | 啟動伺服器的用戶端程式的程式碼身分, 對照已配對用戶端允許清單檢查 ([邊界 1](trust-boundaries.md#邊界-1-mcp-用戶端---rust-mcp-伺服器-stdio-json-rpc-20)) | 已登記的 Mac 上為硬體在場; 否則為軟體備援 | 守住: 橋接只准入這個執行檔、由這個使用者執行、且持有執行秘密 ([邊界 2](trust-boundaries.md#邊界-2-rust-mcp-伺服器---原生訊息主機-橋接-socket-ndjson)) |
| Linux | 啟動伺服器的用戶端程式的程式碼身分, 對照允許清單檢查 ([邊界 1](trust-boundaries.md#邊界-1-mcp-用戶端---rust-mcp-伺服器-stdio-json-rpc-20)) | 僅有軟體備援 | 橋接以同樣的閘門守住; 在場由軟體證明 |
| Windows | 啟動伺服器的用戶端程式的映像雜湊與 Authenticode 發行者, 對照允許清單檢查 ([邊界 1](trust-boundaries.md#邊界-1-mcp-用戶端---rust-mcp-伺服器-stdio-json-rpc-20)); Windows 上的配對見 [CLI 頁面](../cli.md#受信任用戶端-pair-client--revoke-client--list-clients) | 僅有軟體備援 | 橋接守住: 只有這個使用者能開啟的具名管道、相互的映像證明、執行秘密 ([邊界 2](trust-boundaries.md#邊界-2-rust-mcp-伺服器---原生訊息主機-橋接-socket-ndjson)); 在場由軟體證明 |

那一列背後的 Windows 殘餘風險屬於[威脅模型](threat-model.md#殘餘風險-已接受已追蹤); [安全策略中的平台表格](../../../.github/SECURITY.md#platform-support)擁有各機制的狀態。

## 對照便利優先的設計流派

瀏覽器自動化常見的一種設計把便利放在第一位。左欄以界定該流派的各項選擇來描述它, 而瀏覽器對此的反應是關於其他軟體的陳述; 這裡不點名任何產品。

| 比較點 | 便利優先的設計流派 | 本專案 |
| --- | --- | --- |
| 誰能觸及橋接 | 一個對任何本機程序開放的 localhost 連接埠 | 只有這個執行檔、由這個使用者執行、且持有執行秘密 ([邊界 2](trust-boundaries.md#邊界-2-rust-mcp-伺服器---原生訊息主機-橋接-socket-ndjson)) |
| 偵錯連接埠與其橫幅 | 一個隨時對任何本機程序開放的偵錯連接埠; 瀏覽器的偵錯橫幅只在有用戶端附加時顯示, 所以在兩次附加之間使用者什麼都看不到 | 沒有偵錯連接埠; 橫幅只在由偵錯工具支援的工具或選擇加入的 CDP 模式持有附加時顯示 ([工具風險矩陣](tool-risk-matrix.md)標示了哪些工具) |
| 預設存取 | 從第一次呼叫起就能完整存取每個網站 | 頁面操作與讀取只在使用者已核准的網站上執行, 分頁標題與 URL 除外, 它們不需核准; 風險最高的工具在主機持有的策略下預設關閉 ([工具風險矩陣](tool-risk-matrix.md)) |
| 逐動作確認 | 無 | 預設情況下, 需要確認的動作在頁面觸及不到的視窗上確認 ([工具風險矩陣](tool-risk-matrix.md)列出了它們), 其中風險最高的兩個在已登記的 Mac 上需要硬體在場; 放寬任何閘門都是一次以在場為閘門的策略變更 ([確認預設值](../../../.github/SECURITY.md#page_eval-and-confirmation-defaults-fail-safe)) |
| 本機惡意軟體 | 宣告不在範圍內, 且什麼都不做 | 同樣不在範圍內, 但橋接拒絕成為最廉價的那扇門: 在 macOS 與 Linux 上, 不同的同一使用者程式會在 socket 處被拒絕, 而一旦有一個用戶端配對, 每個用戶端程式都必須符合允許清單, 且配對需要使用者在場 |

## 未來變更的規則

本頁為審查標準增加一條規則: 每一項與安全相關的變更都要指出它移動了本頁的哪一列以及方向, 或說明沒有任何一列移動以及原因。[安全策略中的審查標準](../../../.github/SECURITY.md#security-relevant-changes-review-bar)定義了哪些變更算數。
